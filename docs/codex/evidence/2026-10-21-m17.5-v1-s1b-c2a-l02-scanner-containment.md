## Authority and scope

The M17.5 Trust & Assurance ADR, sections 2/7 and the neutral status boundary,
prohibits repository heuristics from issuing certification. An independently
issued authenticated artifact must identify issuer, subject, framework/version,
scope, validity and verification/revocation basis. This scanner has no issuer
artifact and cannot produce CERTIFIED, ATTESTED or an equivalent credential.
This change removes an old scanner assurance semantic; it creates no assurance
projection, governance model, external artifact evaluator or Hub implementation.

## Algorithm and public contract disposition

The old chain combined RLS/consent/audit/test/linter/agent/dependency/auth signals,
criticalPct <=15%, highPct <=30%, heuristic regulation statuses, CI/audit signals
and overallScore >=60 into a tier hierarchy. It then mapped tiers into an
aggregate summary score and a valid/pending SOC2 graph certificate.
The entire production algorithm was deleted; it was not renamed into basic,
maturity, coverage, likelihood or readiness levels. The original implementation
is retained only as a clearly marked test oracle copied from the starting HEAD,
with a local historical type and adjusted type import. Git preserves its source.

## Empty, clean and acquisition semantics

An empty scan returns the same non-authoritative envelope, empty technical
collections and counts. A reused scanner resets previous observations. toGraph
also handles an empty scan without inventing a certificate or throwing on missing
arrays. Zero detected risks, CI, tests and audit/log files cannot cause a positive
assurance conclusion. Missing local directories reject with ENOENT; no positive
fallback result is fabricated.

Acquisition reports discoveredFiles, analyzedFiles, unreadFiles and explicit
limitations. Oversized or failed reads do not become evidence. Local supported
paths use forward slashes, matching existing analyzer conventions on Windows.
The local extension filter (including its exclusion of .env.example), remote
200-file limit and upstream empty-tree/failure ambiguity remain limitations.
Remote null content stays unread; an acquired empty string is retained as a read
file, not interpreted as compliance. No completeness/coverage percentage exists.

Tier and zero-risk fixtures control acquisition only, including a complete
remote-style file map. Real production analysis, detectors, mapping, exports and
result objects execute. The test oracle proves each former tier precondition;
it never supplies the current scanner's result. Local filesystem tests separately
cover high-risk agents/models, PII + consent, empty/reused state, oversize partial
reads and missing source. No live GitHub or hosted acceptance is claimed.
