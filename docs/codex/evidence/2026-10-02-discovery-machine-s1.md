S1-B — GitHub adapter hardening (`github-source-adapter.ts`, `source-adapter.ts`):

- The constructor validates owner/repo/ref against the Commercial V0 constraint. Valid input is kept verbatim, so `describeSource()` and every existing identity are unchanged.
- Every GitHub request uses `redirect: 'manual'`. A 3xx or `opaqueredirect` response raises `GitHubRepositoryRedirectedError` ("GitHub repository redirected - rebinding required") for:
  - repository metadata;
  - commit resolution;
  - tree enumeration.

  A content read returns `ok: false` with the same reason and no content.
- `SourceAdapter` gains the optional, vendor-neutral `resolveProviderSourceIdentity()` and the `ProviderSourceIdentity` type. The GitHub implementation:
  - reads `GET /repos/{owner}/{repo}`;
  - requires a positive safe-integer `id` and a parseable `full_name`;
  - verifies normalized `full_name` equals the configured normalized locator, failing closed otherwise;
  - returns `{providerCode: 'github', providerSourceId: String(id), observedLocator: full_name}`;
  - memoizes the result and does not cache failures.
- `DiscoveryPipeline` does not call this capability; a test proves it. S6 owns wiring it in.

Commercial V0 constraint, not a statement about every name GitHub permits:
- owner: ASCII `[A-Za-z0-9-]`, no leading or trailing hyphen, at most 39 characters;
- repository: ASCII `[A-Za-z0-9._-]`, at most 100 characters, not `.` or `..`, no `.git` suffix;
- anything else (whitespace, `/`, `\`, `:`, URL or path forms, non-ASCII including confusables) is rejected, not reinterpreted.

The provider immutable ID is authenticity metadata only. It is not a GOV IA identity, a namespace or a registry.

## D. Identity compatibility result

- `sourceConnectionId` matches the pre-S1 formula byte for byte across:
  - all golden GitHub vectors, through the real adapter path (`describeSource` → `createSourceConnection`);
  - legacy and non-GitHub descriptors (local paths, a space-containing display name, non-ASCII, GitLab-style);
  - a randomized corpus of 509 display names × 4 provider codes, through both `deriveSourceConnectionId` and `createSourceConnection`.

That event is DETECTED → PROPOSED with a `DETERMINISTIC_RULE` / `PASS_THROUGH_V1` / `1.0` actor. No second event namespace exists. Parity across `review_subjects`, `review_audit_events`, `review_audit_event_evidence` and the outbox remains an S4 gate.

## F. Negative tests

- **Owner:** empty; leading or trailing whitespace; inner space; `/`; `\`; `:`; URL; leading or trailing hyphen; `.` or `..`; dotted or underscore owner; full-width and Cyrillic confusables; accented letters; over 39 characters; trailing newline.
- **Repository:** empty; whitespace; `/`; `\`; `:`; host or URL forms; `.` or `..`; `.git` / `.GIT`; accented, Cyrillic and full-width confusables; over 100 characters; tab.
- **Locator strings:** no slash, extra segments, leading, double or trailing slash, URL.
- **Ref:** empty; leading or trailing space or tab; NUL; LF; DEL; C1 control.
- **Adapter:** rejects all of these with `SourceIdentityError` and does not echo the input.
- **Redirects:** 301, 302, 307 and 308 each on repository metadata, commit, tree and content (16 cases), plus `opaqueredirect`. None is followed: each makes exactly one request per resource and returns no content.
- **Provider identity:**
  - `id` missing, string, 0, negative, fractional or above `MAX_SAFE_INTEGER`;
  - `full_name` missing, non-string or with extra segments;
  - `full_name` mismatched in repository or owner (transfer);
  - array or null body;
  - no token leakage on failure.
- **PROPOSE parser:**
  - rejected extra keys: `actor`, `newState`, `previousState`, `rule`, `ruleVersion`, `role`, `organisationId`, `reviewSubjectId`, `commandId`, `eventId`, `bindingId`, `payload`, `sql`;
  - an own JSON `__proto__` key;
  - symbol keys;
  - null, scalars, arrays, inherited-property objects and class instances;
  - missing or undefined keys;
  - wrong run or finding shapes, including surrounding whitespace.
- **Intake parsers:**
  - tenant, principal, capability, revision, normalized-locator and connection injection on open-run;
  - initial-state injection on the subject selector;
  - prefix, pattern and limit or tenant injection on the mapping lookup;
  - non-terminal completion status; empty evidence array;
  - an implicit `propose` flag on admit-finding;
  - `organisationId` in a technical proposal;
  - `organisationId`, `sourceScope`, `sourceSystemId` and `providerCode` in a snapshot;
  - a snapshot `authorizationState` other than `UNKNOWN`.
- **Identifiers:** uppercase, whitespace or non-UUID binding and principal IDs; binding revision 0, negative, fractional, NaN or unsafe.
