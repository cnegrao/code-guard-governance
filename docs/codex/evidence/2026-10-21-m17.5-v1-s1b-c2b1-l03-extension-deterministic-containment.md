## Contract and presentation

Every newly generated deterministic report contains this frozen literal boundary:

```json
{
  "kind": "TECHNICAL_SCAN",
  "source": "DETERMINISTIC_TECHNICAL_SCAN",
  "authority": "HEURISTIC_NON_AUTHORITATIVE",
  "scope": "SCANNED_INPUT_ONLY",
  "compliance_determination": false,
  "legal_conclusion": false,
  "certification": false,
  "assurance": false
}
```

The object also carries `findings`, `summary_counts`, `reported_counts`,
`findings_omitted`, `detection_state`, `summary`, `recommendations`,
`files_analyzed`, `acquisition`, `detectors_run`, `plan`, `detector_access`,
`timestamp` and `limitations`. There is no score, grade, complianceMapping,
aligned/compliant/certified/readiness result or hidden legacy report copy.
Negative type fixtures also reject importing the removed legacy contracts and
changing the boundary into affirmative authority.

Zero findings in provided input means only:
“No findings were detected by this scan in the analyzed input.”
The immediately visible limitation says:
“This does not establish legal compliance, framework satisfaction, control
effectiveness, certification or completeness. It is not a legal conclusion or
assurance.” The UI uses neutral colors and no success/checkmark/pass state.
Absence of GDPR or AI Act findings produces no framework result at all.

NO_FILES and EMPTY_INPUT produce NOT_ASSESSED; partial/unknown acquisition is
preserved with an explicit no-completeness limitation. No positive conclusion is
created for unread, empty or unlisted input. Quick Scan scope is only the editor
input, never the repository. CLI reads that throw stop before creating a report.

Paid, Free and credit access share exactly the same authority boundary. Credit
access no longer masquerades as a Professional plan in report metadata: the
actual plan is retained, with a separate CREDITS detector-access label. Existing
detector unlocking and Free display limits remain. Counts include all detected
findings; shown/omitted counts prevent hidden findings becoming a zero result.

Detector patterns, severities, matches, rule IDs, line numbers and existing fix
payloads remain. Minimal message-only changes in GDPR/AI Act/PCI/CCPA remove
statutory-violation/high-risk-system declarations inferred from regex matches.
Recommendations are source-context review or the detector's existing fix
description, not framework satisfaction.
