## Numeric Safety Amendment

The issue existed in the original partial candidate and is retained in the audit trail. Real PostgreSQL **17.11 / 170011** and pgvector **0.8.7** reproduced a finite query `[3e38,0,0]` with finite nonzero `vector_norm`, but raw cosine against `[1,0,0]` produced similarity zero and an actual false NO_MATCHES at threshold 0.5. Raw self-cosine of both `[3e38,0,0]` and `[1e-30,0,0]` produced NaN. The [original probe](../../../.artifacts/agent/sr2-a2-numeric-probe.json) and [script](../../../.artifacts/agent/sr2-a2-numeric-probe.ts) preserve those observations. The prior gate was `SR2_A2_STOP_ARCHITECTURE_DRIFT`; it was not an accepted implementation.

The installed pgvector source, `VectorCosineSimilarity` in [vector.c](../../../out/pgvector-tooling-20261021/pgvector-v0.8.7/src/vector.c), accumulates dot product and squared norms in float32. Large values overflow and tiny values underflow that arithmetic. A finite double-precision norm is insufficient to prove raw cosine safety, and PostgreSQL NaN comparison semantics make IEEE self-equality checks unsuitable. The owner-reported independent adversarial review confirmed the same root cause.

The approved repair leaves the input domain unchanged: exact dimension 1..16000, finite float32-representable components, at least one float32-rounded nonzero component. No magnitude envelope, producer normalization requirement, new identity field, normalized flag/column or A1 rewrite was added. Node validates and copies float32-rounded components; it does not normalize or compute a sum-of-squares safety test.

The SQL reader validates the query and calls the actual extension namespace's `l2_normalize(p_query)` **exactly once**, storing `v_query_unit`. Every score is `1 - (l2_normalize(r.embedding) OPERATOR(<resolved-schema>.<=>) v_query_unit)`. The stored normalization is performed for each latest eligible scored representation. Cosine, threshold inclusivity, latest-before-eligibility/no-fallback selection and deterministic relevance/subject/representation ordering are unchanged.

A materialized aggregate checks **all scored rows**, before threshold/limit admission, with `(relevance BETWEEN -1 AND 1) IS NOT TRUE`. An invalid score causes `TECHNICAL_NUMERIC_INVARIANT` / SQLSTATE `XX000`; no hits or no-match/withheld/invalid-query result is returned. NaN, positive/negative infinity, null and out-of-range score injections each raised that exact internal error at thresholds -1 and +1 with limit 1. Every injected definition was transactional and restored. The Node adapter test maps that exact error through its existing generic INTERNAL_ERROR path without leaking the SQL message. No new unavailable reason exists.
