## Before and after

Previously the three `/api/audit` routes extracted only organisation ID and
called `services/audit.ts` → `repositories/audit.ts`. The repository used direct
service-role source SELECTs with application filtering, global verification,
raw sequence details and totals/offsets. Missing verifier rows became false;
the UI rendered only VALID/BROKEN, exposed global hashes and used an unbounded
"tamper-proof" claim. An integrity fetch failure was silently ignored.

Now each route retains the complete `VerifiedGovernancePrincipal` from
`requireVerifiedGovernancePrincipal()` and directly calls the committed
`lib/governance/ledger-read.ts` adapter. Its three principal-bound RPCs recheck
persisted eligibility before reads. `service_role` remains transport only.
No request field constructs or overrides principal organisation, actor,
timestamps or exact credential epoch. No shared read cache is introduced.

| Route | Current contract |
|---|---|
| GET `/api/audit/integrity` | `verifyTenantLedger(principal)`; closed V2 envelope, all four status and all three history states preserved |
| GET `/api/audit/events` | `listTenantLedgerEvents(principal, {limit,cursor,eventType})`; only limit 1–100, opaque cursor and exact `event_type`; duplicate/unsupported parameters rejected |
| GET `/api/audit/events/[id]` | Strict `V2:<uuid>` / `LEGACY:<uuid>` parser → `getTenantLedgerEvent(principal,kind,id)`; foreign/missing valid IDs return the same 404 |

All responses, including errors, carry `Cache-Control: private, no-store`.
Client fetches use `cache: no-store` and AbortController. Numeric global detail
URLs return sanitized 400 without any DB call; no translation/lookup occurs.
The browser URL encodes the opaque handle. The route receives the decoded path
parameter through Next.js; it never performs permissive numeric parsing.

| Error/result | HTTP | Public response behavior |
|---|---|---|
| SessionAuthenticationError | 401 | PASS | Not authenticated; no integrity state |
| LedgerReadAuthorizationError | 403 | PASS | Ledger access denied; no tenant metadata |
| RangeError / invalid request | 400 | PASS | Invalid audit request; same malformed/foreign/missing cursor envelope |
| LedgerReadUnavailableError | 503 | PASS | Ledger reading temporarily unavailable |
| Unexpected error | 500 | PASS | Audit request failed; exception/DB text suppressed |
| Verifier UNKNOWN | 200 | PASS | Ordinary UNKNOWN integrity result; never an exception solely for UNKNOWN |
| Missing/malformed verifier row | 200 | PASS | Committed adapter produces UNKNOWN, never fabricated EMPTY/BROKEN/VALID |

## Presentation and read lifecycle

| Current V2 state | Visual and wording |
|---|---|
| VALID | Green; "V2 ledger integrity verified"; retained current tenant V2 scope and activation/version shown |
| BROKEN | Red; "V2 ledger integrity issue detected" |
| UNKNOWN | Amber; "V2 ledger integrity could not be established"; no checked count/verified-through |
| EMPTY | Neutral grey; "No V2 ledger entries to verify"; no positive assurance |

History is a separate section, not a second integrity result:
`LEGACY_GLOBAL_ONLY` explains that pre-cutover global history is not tenant-local
cryptographic verification; `NO_LEGACY_ENTRIES` is neutral informational text;
`UNKNOWN` explicitly says history has not been established. No legacy global
verification status is presented.

The heading now reads "Tenant audit records and V2 ledger integrity". The page
explains that retained-record chain consistency does not establish governance
correctness, compliance, control effectiveness, real-world completeness or
certification. There are no scores, percentages or affirmative assurance labels
on events merely because the chain is VALID.

The list uses only the closed event fields: V2 tenant sequence or Legacy,
timestamp, event type, description, subject, nullable actor and payload authority.
Detail shows kind, V2 tenant sequence (not applicable for legacy), event/subject/
actor metadata, event and recorded timestamps, history and retained payload.
The old Hash Chain section is removed. Legacy payloads visibly remain
`LEGACY_NON_AUTHORITATIVE`; V2 payloads show `RETAINED_RECORD_ONLY` and the
separate legacy-field limitation. Beside the payload:
"Ledger integrity does not establish the semantic truth of payload contents."
No payload is interpreted as an approval or authoritative oversight fact.

Pagination is first page → Next via `next_cursor`; First page restarts the
request. Exact event type changes clear the cursor. There is no Previous offset,
total, totalPages, page arithmetic, aggregate RPC or "showing X–Y of total".
Search, subject, actor and date-range controls are removed. Legacy metrics
`total_entries`, `latest_sequence`, `entries_last_30_days`, event-type counts
and the boolean integrity metric are removed rather than reconstructed.

Each client result belongs to a URL/revision key. A changed request/refresh
synchronously masks the prior result as loading; effect setup drops its data,
cleanup aborts and invalidates the old request, and late responses cannot win.
Failures replace success with explicit unauthenticated, denied, unavailable,
invalid or missing-record UI. Integrity and event reads start independently;
changing event pagination does not re-verify the chain unnecessarily.
