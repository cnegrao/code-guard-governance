## Preparation and explicit activation

Applying the new migration **does not activate V2**: no epoch/head/genesis/entry
or legacy reference is inserted. It installs the checked write path, capture,
source guard and coverage check while quarantining the old application append
and source DML. During this prepared/inactive interval, writes fail closed;
there is no compatibility fallback or promise of rolling deployment continuity.

`gov_repo.ledger_v2_activate(text[])` is an owner-only **SECURITY INVOKER
procedure**, owned by `postgres`, not a new operator HTTP/RPC endpoint. It
requires the exact source-inventoried acknowledgement
`ARRAY['discovery_scan','talk_governance_logging']`. Application roles have no
EXECUTE. The acknowledgement is not a claim to discover untracked hosted
writers; hosted rollout requires its own authorized inventory/drain.

Activation acquires the same transaction advisory cutover guard as internal
append, then ACCESS EXCLUSIVE source/epoch/global-head locks. It rejects any
existing epoch, unexpected initial sidecar state, application raw/global
verifier capability or source DML, application V2 table privilege, disabled or
misbound capture/coverage/source trigger, and mismatched write/serializer body,
owner, definer, search_path or volatility fingerprints. The function inventory
is pinned in the new migration; historical fingerprints remain unchanged.

Only after draining writers does it author `activated_at`, a random immutable
activation UUID, SHA-256/version 2, serialization 1 and migration identity,
actual legacy tip sequence/hash, and singleton global head. It also maps old
rows to opaque random legacy reference UUIDs, without tenant hashes. All these
changes commit together. Any exception rolls the entire activation back.

Legacy policy: **allow an internally broken legacy chain when its actual tip
is representable as a 32-byte hash**; seed the stored tip without declaring it
valid. A malformed/non-32-byte tip aborts. No global verifier result is consumed
by generation. Empty global history seeds the original
`SHA256('CODEGUARD-GENESIS-2026')`, high-watermark 0. No history is rehashed or
rewritten. Every pre-cutover row remains **LEGACY_GLOBAL_ONLY** permanently.

## Write and lock model

The existing `ledger_append(varchar,text,varchar,uuid,uuid,inet,uuid,jsonb)` keeps
its signature, technical owner, return identity and historical V1 hash format.
Its body is replaced only in the additive migration. It has no inactive branch,
SKIP LOCKED, asynchronous delivery or best-effort capture.

Lock order: persisted eligibility basis (organisation → user → sorted roles,
FOR SHARE), global advisory cutover guard `(175,2)`, singleton global head
FOR UPDATE, uniquely arbitrated tenant genesis/head, tenant head FOR UPDATE.
Source INSERT also takes its ordinary relation lock. The advisory guard makes
cutover and the private append agree without granting broad table DML to the
technical executor; the explicitly locked head remains predecessor authority.
Eligibility and boundary/internal lock waits are bounded at 5 seconds. There
is no automatic application retry; transaction errors propagate, with no
global-only downgrade. Transactions retaining multiple appends retain the
global guard; new multi-tenant batches must follow the ADR's sorted org order.

AFTER INSERT `ledger_v2_capture`, SECURITY INVOKER in the internal writer's
context, creates one random chain/genesis lazily per organisation. The existing
UNIQUE organisation and composite keys arbitrate creation. Sequence starts at
1, predecessor is the frozen serializer's genesis hash. The locked transactional
tenant counter consumes no sequence on abort. A distinct tenant-entry UUID
identifies the retained event; source UUID duplication in legacy history is
still legal. Unique source global sequence prevents duplicate capture.

The capture advances **both** tenant and global heads before returning. That
also supports callers using IMMEDIATE constraints. The source, genesis, tenant
entry and both heads are one transaction. Source-record/head/canonical-coverage
checks compare the actual retained fields, source UUID, final global tip and
tenant final sequence/hash/count. The frozen entry-structure constraint still
checks predecessor/source identity.

Both checks are defined DEFERRABLE INITIALLY DEFERRED. The checked wrapper
flushes exactly `ledger_v2_entry_structure` and `ledger_v2_coverage` IMMEDIATE
while it still runs as `postgres`, then restores DEFERRED. Otherwise invoker
triggers at service_role COMMIT would require forbidden V2 reads. Application
roles cannot enqueue source/sidecar writes outside this boundary; no pending
ledger checks escape its authorized context. No definer helper was added.

Committed global serial gaps from aborted writes are permitted. Neither tenant
preimage includes source global sequence, global predecessor/hash or verifier
result. V1 text/timezone/JSON hash semantics are retained; V2 remains the frozen
typed canonical byte contract, never V1 text concatenation.

## Immutability and product behavior

The existing immutable-core/no-delete rules are retained. They may suppress
updates instead of throwing; tests require unchanged bytes. The new source
guard covers post-cutover organisation, description, actor IP/session,
event_timestamp and every other V2 captured source field. Legacy-only omitted
fields keep their prior mutability. QES anchor/anchor_at remain excluded and
owner-mutable. No conflicting legitimate mutable captured field was found.
Tenant evidence cannot be updated, deleted or truncated; head identities cannot
be reset through these primitives. There is no deactivation, reset-genesis,
repair-delete, rehash or global-only fallback operation. Future recovery is
forward-only: preserve evidence, append supported corrections or deny writes.
Administrator DDL rewriting the entire evidence/head boundary remains outside
unkeyed-hash integrity guarantees.

Reconfirmed active canonical dashboard writers are exactly discovery scan
(`app/api/discovery/scan/route.ts`) and Talk governance logging
(`services/talk.ts`, with principal plumbing in its API route). Repository
search and the new source-contract test found no third active writer. Historical
setup/migration artifacts and tests are not runtime writers.

Both use server-only `appendLedgerEvent` and the five existing principal fields,
preserving exact epoch text. RPC errors, thrown transport failures and missing/
malformed receipts throw a sanitized `LedgerWriteUnavailableError`; routes return
503 `Ledger recording unavailable`. No raw fallback or retry. Discovery stops
at the failed logging step and does not return scan success. Earlier independent
memory-indexing effects/events may already have committed; this is not a claim
of a whole-scan transaction. Talk preserves router/LLM/fallback answer semantics
on success, and response logging failure propagates even from the LLM try/catch.
Earlier query/runtime observations may remain after a later failure.

Existing OPERATIONAL_LEGACY / NOT_ACTIVE discovery labels and Talk payload
semantics are retained. Integrity concerns retained committed records, not
producer completeness or governance truth. There is no guarantee that every
real-world Talk action is logged. Identical append submissions intentionally
create distinct retained records; this API has no idempotency key.
