## Verification algorithm and complete-population boundary

After session authorization, **one SQL CTE statement** acquires the active
epoch, own genesis/head, complete own V2 entry population, corresponding own
post-cutover source population, and own legacy existence in a single statement
snapshot. No independent RPC results or PL/pgSQL integrity reads are stitched
together. No tenant write lock, global head, global verifier result, source
global hash or source global predecessor participates in tenant verification.
Internal source sequence is used solely for source correspondence/cutover.

The fixed supported maximum is **10,000 source rows and 10,000 captured rows**.
Each acquisition fetches at most 10,001 rows through own-tenant indexes; the
extra row establishes overflow. Overflow returns UNKNOWN before assurance;
there is no client range, green prefix, count percentage or integrity score.
One supported active epoch and supported finite/32-byte metadata are required.
Missing dependency, unsupported encoding/version, unavailable or unexpected
metadata, and acquisition errors yield UNKNOWN. Authorization is outside that
exception boundary. Transport errors remain typed request unavailability.

For a complete supported population, recompute genesis and **every tenant hash**
with the unchanged canonical V2 serializer, then compare tenant/org, chain,
activation, versions, tenant entry UUID, predecessor, sequence continuity,
first-recorded timestamp and final head sequence/hash/committed count. A FULL
JOIN of the bounded complete source/capture sets checks source UUID, own org,
all captured canonical content and bidirectional coverage. Duplicate source
capture and duplicate tenant identity are independently checked. Specific
observed identity, digest, coverage, sequence or head contradictions are BROKEN.
Owner rewriting the entire trusted epoch/chain/head remains outside the ADR's
unkeyed-hash guarantees; no tamper-proof or producer-completeness claim follows.

| Result | Meaning |
|---|---|
| VALID | Complete authorized current V2 chain and source correspondence verified through captured head in one snapshot. Retained-record integrity only. |
| BROKEN | Complete supported acquisition identifies a specific tenant-local inconsistency; bounded category and optional own tenant sequence only. |
| EMPTY | Authorization and active epoch established; no own V2 source/capture and no unexpected head/genesis. No positive assurance. |
| UNKNOWN | Complete supported verification cannot be established. Checked count and verified-through are absent/null; never converted to BROKEN or EMPTY. |

The independent history axis is `LEGACY_GLOBAL_ONLY`, `NO_LEGACY_ENTRIES`, or
`UNKNOWN`. No V2/no history => EMPTY + NO_LEGACY_ENTRIES; legacy only => EMPTY +
LEGACY_GLOBAL_ONLY; valid V2 plus legacy => VALID + LEGACY_GLOBAL_ONLY. Legacy
global validity cannot create tenant VALID. The envelope includes own org,
chain/activation/version scope, activation time, checked count as decimal text,
verified-through only for VALID, the fixed scan bound and explicit limitations.
It does not author a last-verified timestamp merely because a request ran.

## Events, detail and authority

List accepts page size 1–100 (default 50), optional literal exact event type
(maximum 120 characters), and optional cursor. Order is descending tenant
sequence for V2, followed by legacy rows in private descending source order.
Each branch fetches at most page-size + 1 candidates. Returned page contains
only own events and an optional next cursor; there is no total/count endpoint.
Two-phase ordering is deterministic; pagination is a current keyset traversal,
not an exported long-lived snapshot or an integrity verification of pages.

Cursor format is `V2:<tenant-entry-UUID>` or `LEGACY:<legacy-ref-UUID>`.
The UUIDs are the existing random opaque identities, not encoded global order.
The DB resolves an anchor only within the authorized organisation; foreign,
missing and malformed cursors fail closed with the same sanitized cursor error.
There is no globally reusable continuation or cross-tenant count oracle.

Detail accepts kind plus opaque UUID. Both foreign and nonexistent valid UUIDs
return SQL NULL, with identical envelopes. Invalid shape/kind is a request
error. Neither RPC accepts a raw global sequence as an event identity. Explicit
projection excludes source/global IDs, sequence, hash, predecessor, global
status/count and tenant hashes. Own tenant sequence is returned only for V2.
List/detail do not claim cryptographic validity merely by returning an event.

Payload is retained evidence content. All legacy records carry
`LEGACY_NON_AUTHORITATIVE`; V2 records carry `RETAINED_RECORD_ONLY` and preserve
the explicit `legacy_payload_authority=LEGACY_NON_AUTHORITATIVE` limitation for
known legacy oversight/default fields. A semantically false legacy oversight
payload coexists with V2 VALID in the real PG test and does not become governance
truth, verified human oversight, control effectiveness, compliance or certification.

`apps/dashboard/lib/governance/ledger-read.ts` is server-only and requires
`VerifiedGovernancePrincipal`. It calls only the three new RPCs, preserves both
closed status axes, transports exact credential epoch text, validates envelopes,
and strips unexpected envelope fields. Missing/malformed verification results
become UNKNOWN; malformed pages/details fail unavailable. Authorization errors
are a separate class. Transport errors, including thrown RangeError, are
sanitized. There is no legacy repository, global verify, table SELECT or client
fallback. The module is not imported by any active route/repository/service.

## Real security and snapshot evidence

The new PG suite covers independent valid A/B chains; A and B hash corruption
without changing the other's result; missing middle/tail/all capture; extra and
dangling capture; duplicate capture; source-only drift/deletion; source UUID,
tenant UUID, chain/activation/predecessor/genesis and head faults; unsupported
versions; missing/malformed metadata/dependency; both population overflow paths;
all three RPC principal denial cases; exact own detail; foreign/nonexistent
V2/legacy identities; deterministic paging, literal filters, page bounds and
tenant-bound cursors; real ACL denial and no global metadata in envelopes.
Owner-only corruption transactions roll back all DDL/bytes. Application roles
cannot acquire those tamper capabilities.

The snapshot test uses real writer, reader and monitor backends. Writer appends
but retains an uncommitted source/capture/head. A fixture-only wrapper gates the
reader's first canonical genesis recomputation with an advisory lock, delegates
to the unchanged serializer and is removed afterward, restoring its original
identity/body/ACL. `pg_stat_activity.wait_event_type='Lock'` and
`pg_blocking_pids()` prove reader→monitor blocking. The writer commits while
the verifier is inside its integrity statement. On release the result is the
**coherent pre-append VALID / 3 entries / through 3**; the next call is
**coherent post-append VALID / 4 entries / through 4**. No mixed population/head
VALID is observed. Sleep alone is not used as concurrency evidence.

Owner-only legacy corruption makes the global verifier BROKEN while the tenant
result remains exactly unchanged. Renaming the global verifier out of reach
also leaves tenant verification unchanged. Real adapter → service-role SQL RPC
→ PG17 checks all three calls, pagination, exact/foreign detail, foreign cursor,
organisation spoofing and exact credential staleness. This substitutes only
local SQL transport; it is not hosted HTTP/PostgREST acceptance.
