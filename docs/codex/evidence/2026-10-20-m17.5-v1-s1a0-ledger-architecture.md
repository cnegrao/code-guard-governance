## Source findings and decision

The [new additive ADR](../../architecture/ADR-GOVIA-TENANT-LEDGER-INTEGRITY-v2.md)
contains exact commit/line locators for schema, append/hash/predecessor selection,
global verifier, grants/owners, consumers and established principal read patterns.
Current model: **GLOBAL_INTERLEAVED**. At sequences A1, B1, A2, A2 points to B1;
filtering to A rows is not valid tenant-chain verification.

Original hash excludes organisation and sequence, uses unframed text casts and
has a global genesis. SKIP LOCKED on the global tip is not a stable head lock;
concurrent empty/locked-tip appends require explicit future remediation. The
current table's immutable rule does not cover all tenant/identity fields needed
by V2. No claim is made about actual hosted history or deployed fork presence.

Options compared: A global-only internal verification (safe interim quarantine,
no tenant integrity); B replacement (history/compatibility loss if rewritten);
C synchronous dual-chain (atomic capture, extra state and global write cost);
D independent tenant ledger/anchor (clean separation, but asynchronous delivery
or frozen-global semantics beyond the minimum path).

Selected architecture: **dual-chain V2 with separate normalized tenant integrity
tables**, using D's separate-storage form as the synchronous realization of C.
Keep original global history and append identities. Do not fabricate per-tenant
history or silently relabel the global hash algorithm. Global serialization is
an accepted cost of continued synchronous global continuity; tenant verification
is independent of global verification and other tenant rows.

## Frozen design boundaries

| Concern | Decision / ADR section |
|---|---|
| Historical semantics | §3: legacy rows remain LEGACY_GLOBAL_ONLY. No reconstructed/backfilled tenant hashes. Opaque legacy identity mapping conveys access only, not new evidence. |
| Cutover/genesis | §3: one guarded atomic activation UUID/version/UTC instant and private legacy high-watermark. Tenant genesis binds org/chain/activation/version, never global hash/sequence. Lazy tenant first entry is explicit. |
| Data model | §4: immutable epoch/genesis/entries, mutable global/tenant heads, opaque legacy references; composite org/source binding, tenant uniqueness/order and indexes; no historical row rewrite. |
| Hash domains/serialization | §5: distinct tenant genesis/entry domains, SHA-256, typed length framing, explicit field order/JSON/number/UTC-microsecond encoding and immutable numbered vectors. |
| Concurrency | §6: eligibility → stable global head → tenant head; unique first genesis arbitration; blocking locks/no SKIP LOCKED; atomic capture and head updates; committed contiguous tenant sequence. Shared global write availability is disclosed. |
| Verification | §6–8: one SQL snapshot of complete own V2 source/capture/head population; no other-org traversal, no global hash dependency, no green partial scan. |
| Vocabulary | §8: VALID/BROKEN/EMPTY/UNKNOWN; separate LEGACY_GLOBAL_ONLY/NO_LEGACY_ENTRIES/UNKNOWN history axis; denied request has no integrity state. Missing result is UNKNOWN/failure, never automatically BROKEN or EMPTY. |
| Tenant security | §7: established verified-session fields, persisted eligibility revalidated in DB; no app org-only filtering; service_role transport alone cannot authorize. |
| Global future | §9: supported internal platform forensic history, synchronous dual-write; no tenant global result, identifiers, count/status oracle or error leakage. |
| Payload/authority | §9: record integrity only. LEGACY_NON_AUTHORITATIVE oversight/defaults remain so even in VALID V2. No new canonical fact/kind/edge/Passport family/Authority Policy permission or compliance claim. |
| Privileges | §7: four thin principal-bound definer RPCs (planned delta +4), pinned paths, explicit revokes/exact grants; internal legacy append/global verifier not application-callable; invoker capture/serializer/guards. No privilege mutation performed. |
| Failure/rollback | §10: atomic activation failure rolls back; after first committed V2 entry recovery is forward-only with preservation and fail-closed reads, never global-only fallback or genesis reset. |

Existing trusted server session verification remains the authentication boundary;
