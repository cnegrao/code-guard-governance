A factual statement describes inspected code and historical local verification only; it cannot imply deployed operation. Partial proof permits only the implementation-evidence wording, never the unexecuted behavior. S0 PROVEN is not commercial approval. No current CI/hosted verification is imported.

For TA-C01–TA-C34, FACTUAL_CAPABILITY_ONLY is the maximum defensible class for bounded repository wording; publication is still INELIGIBLE pending independent exact-text, currency and exposure review. Limitations/counterevidence may be disclosed internally without becoming a positive capability claim.

Framework mapping/applicability UNKNOWN and requirement sufficiency NOT_ASSESSED remain explicit even for factual claims. They never silently authorize alignment or readiness. Claims using any pending-source framework cannot be eligible for alignment/readiness. Broad legal compliance has no eligibility path in V0. Certification and attestation stay NOT_ASSERTED; source publications and heuristic code are not external issuer artifacts.

Every proposed presentation excludes L01/L02/L03/L04 as assurance inputs, but actual exposure is UNKNOWN and unreviewed. This draft exclusion is not runtime containment. Reliance on or exposure of L01/L02/L04 fails closed while NEEDS_CONTAINMENT is open; L03 requires wording/non-authority/exclusion review before assurance exposure. L05 SAFE concerns only the inspected export guard, not dashboard/deployment safety. No legacy surface is fixed here.
